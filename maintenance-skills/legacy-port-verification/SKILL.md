# Legacy Port Verification

Define the tested features, initial state, input timeline, seeds, clocks, path/encoding rules and numerical tolerances before comparison. Execute original and replica separately, retain executable/asset/tool hashes and raw outcomes, then compare outputs, exit status, file effects, state, event ordering and relevant rendering/audio. Missing observations, unexercised branches and mismatched assets cannot pass. Use memory-snapshot-pattern only to locate candidates, not to verify semantics. Distinguish exact file bytes, observed behavior, finite-suite equivalence, function proofs and formal equivalence under stated assumptions. A new OS/ISA executable is normally not byte-identical. Report PASS per scoped feature, and PARTIAL/FAIL/UNVERIFIED for incomplete applications. Do not mark compilation, process liveness or a screenshot as equivalence.
