# Reconstruction architecture

RE-Agent remains the owner of the reconstruction workflow: provider analysis produces artifact-bound Evidence, the autonomous controller retains observations and hypotheses, and existing process/workspace facilities execute bounded candidate builds and comparisons. CLI, MCP, provider setup, Evidence persistence, and controller checkpoints remain shared platform services.

The `schedule_reconstruction_functions` MCP operation is an advisory plan, not execution admission. It authenticates supplied Evidence, resolves it back to the session-owned records, validates a common artifact and provider identity, forms caller-to-callee edges, groups recursive functions into strongly connected components, and emits dependency-ready components first. A function is `scheduled` only when its observed in-scope dependencies are scheduled and the function has body extent, a signature, and a body representation. Missing callees, insufficient function evidence, exhausted retries, and budget-deferred dependencies have explicit blocking dispositions. External callees are excluded only when the source dossier classifies them as external.

The scheduler does not acquire target execution or filesystem authority. It records plans as derived Evidence linked to the session-owned source dossiers and creates an Unknown for incomplete inputs. In-scope caller counts determine priority; provider caller arrays are not used as a substitute for graph edges. The graph is bounded to 100,000 relationships and uses iterative SCC discovery and a dependency-priority queue. Caller-supplied prior attempt counts only inform this invocation: they are advisory, are not persisted as a retry ledger, and do not replace controller checkpoints. A finite function budget can defer a component; cyclic components are kept together. There is no dedicated CLI command in this change.

Dryxio/ReAgent's dependency-order function picker informed this capability. The implementation is native TypeScript and uses RE-Agent's dossier and Evidence contracts; see [the integration review](../third-party/dryxio-integration.md).
