## Immediate work for the supplied gconv binaries

Prioritize one bounded gconv workflow across issues **#4, #5 and #6**, with host-agent instructions from **#2**. Reuse the existing CLI/MCP analysis, process capture, evidence records and function dossiers. Additional tool installations are justified only by a specific analysis gap observed in this workflow.

1. Hash and identify `gconv.exe`, `gconvapi.dll` and `vqdll.dll`; preserve architecture, imports, exports and caller-selected paths. Treat the three files as a dependency set.
2. Use REA static analysis to recover command dispatch and relevant conversion functions, retaining addresses and decompilation evidence. Separate assertions inferred from code from observed runtime behavior.
3. Execute the original through an explicitly configured runtime, retaining backend details, exit status, exact stdout/stderr and input/output artifact hashes. A compatibility runtime is not a native Windows worker and must be described accurately.
4. Recover a declared conversion slice into an independent native macOS implementation. Record unsupported formats and options rather than generating canned output or delegating conversion to the original executable.
5. Run the same input fixtures against original and replica. Compare output bytes and relevant metadata independently. Preserve every difference as a regression case, including errors, truncation and malformed files.
6. Report tested scope, failures and unknowns. Matching output bytes on a finite suite does not prove complete behavioral equivalence; Windows PE and macOS Mach-O executable bytes cannot be identical native executables.

## Implemented bounded #6 contribution

`scripts/lib/file-differential-benchmark.mjs` now exposes `runFileDifferentialBenchmark`. It stages identical inputs into independent fresh work directories, invokes command vectors through REA's existing `runOwnedCommand` lifecycle, retains a JSON report and compares output-file bytes/hashes, UTF-8 diagnostic text and ordinary exit status independently. It does not claim canonical `rea.process-capture` Evidence or operating-system isolation. Timeouts, absent outputs, cancelled runs and diagnostic overflow cannot pass. Unresolved cleanup ownership is propagated to the caller rather than discarded.

Validation: `node --test scripts/lib/file-differential-benchmark.test.mjs` passed **10/10** real process tests, in 4.37 seconds with sandbox escalation for OS process identity inspection. Tests cover exact binary data, independent retained report directories, individual file/stdout/stderr/exit mismatches, absent output, deadlines, output overflow, duplicate case IDs, output traversal and pre-cancellation. This validates the reusable runner, not gconv conversion behavior. The first cold run exceeded the test fixture's initial 3-second command budget; fixture commands now allow 10 seconds, while the dedicated deadline test remains 100 milliseconds.

Durability follow-up: the runner now atomically replaces its JSON journal before execution and after each side/case observation. A later missing input or cancellation retains prior completed comparisons and exposes `reportPath` on the original thrown error. Unresolved cleanup errors preserve their actual owner object and are rethrown unchanged; the persisted report contains only an explicit failure projection. Atomic rename protects readers from partially written JSON; power-loss durability is not established. The bounded author-fixture suite passed **13/13** tests in 4.48 seconds. The three additional checks cover a successful first case followed by a missing second input, actual cancellation between cases, and an explicitly simulated owner fault through the progress callback. The simulated fault is not evidence of real provider cleanup failure behavior. No original applications were launched for this follow-up.
