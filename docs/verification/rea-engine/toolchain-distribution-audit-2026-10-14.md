Repository identity: [`heaven-hm/rea-engine`](https://github.com/heaven-hm/rea-engine). This is a snapshot of one macOS ARM64 development host and the local REA 6.4.0 capability inventory. ## What is actually included

The project already has one REA CLI/MCP server, a bundled agent skill, an autonomous investigation controller, provider interfaces, benchmark harnesses, and optional tool discovery/install profiles. The probe counted 192 MCP tools, 151 CLI commands, and six prompts. These are engine operation counts, not counts of fully verified reverse-engineering integrations.

An actual npm 6.4.0 dry run on this checkout listed 2,137 files (25,034,759 packed bytes; 64,476,207 unpacked bytes). The receipt included all 144 source, build-input, runtime-asset, evidence, and report paths named by the current [benchmark catalog](../../../benchmarks/catalog.json), including all six Batch 2 acquisition manifests and their shared PE inventory; the package guard satisfied its required paths. The nested `benchmarks/gconv/.npmignore` excludes 73 private decompiler-analysis files derived from proprietary GConv inputs while retaining the independently implemented QVM replica and its public report. The package guard rejects attempts to include those private paths. `benchmarks/.npmignore` and `scripts/calculator/.npmignore` exclude locally generated application binaries and compiler caches; the dry run contained zero benchmark build-output paths. Batch 2 original binaries and runtime captures/checkpoints were absent. These are reproducible npm dry-run measurements, not a published package artifact.

App/game replicas, build instructions, reports, and screenshots already in the repository are source-distribution content unless excluded by package rules. The six Batch 1 MIT input binaries are included under their acquisition/license audit; Batch 2 originals and private runtime workers remain excluded.

## Replicas and benchmark outputs

The scan found reconstructed-source and evidence directories for Luhn, TicTacToe, plink, the Batch 1 Windows utility/game ports, gconv's QVM tool, and Batch 2 fd/bat candidates. The npm pack receipt confirms their source/evidence paths are included. Existing benchmark documentation describes the successful scopes and known limits. Batch 2 has source for fd and bat, no independent game replicas, and no packageable proof of whole-application equivalence.

Original binaries are distinct from replicas. Batch 1 has MIT-labeled upstream Windows inputs retained under `benchmarks/native-windows-ports/original-binaries`; TicTacToe carries GPL materials and retained license/source provenance. Batch 2 target binaries and game assets are private and ignored. Do not turn a source package into a target-binary bundle by recursively copying `originals/`, `.runtime-workers/`, `logs/runtime/`, or local build outputs. The target-specific license audit remains authoritative for each asset.

The repository already contains some macOS replica executables in Batch 1. Batch 2's generated `fdmac`/`batmac` binaries are local build outputs and should be reproduced from checked-in source with the recorded build command on each host; they are architecture-specific and are not portable package payloads. The per-target evidence reports determine whether a feature passed. No aggregate “all apps included and complete” claim is supported.

## Host check and gaps

The discovery snapshot reported healthy Apple Clang 16, LLDB, radare2, Rust 1.97.1, .NET 10.0.400, FFmpeg 9.0.2, Z3, and selected Python modules. It reported missing GDB, Rizin, Frida CLI, RenderDoc, angr, and Hopper. The Python module checks do not establish hooks, whole-target parsing, symbolic execution, or cross-platform builds.

REA's doctor also found the installed skill stale (version 37 versus expected 43), many registered client configurations missing/stale, and the overall host unhealthy. Refreshing registrations is host-specific state and is not solved by bundling. Windows and Linux package/tool health still need native CI evidence.

## Redistribution gate

The project can ship its own engine code and compatible skill under the repository license, plus exact third-party material only with verified terms, provenance, notices, dependency completeness, and platform-specific hashes. “Open source” alone is not the packaging decision. The Frida aggregate bundle explicitly marks public redistribution unapproved; this audit preserves that status. Cheat Engine is excluded until its publisher terms clearly authorize redistribution. No proprietary binaries, user-installed commercial tools, original Batch 2 targets, credentials, or private worker images belong in the public package.
